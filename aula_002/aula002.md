1 — A história das linguagens é uma árvore com galhos, não uma escada onde cada degrau apaga o anterior. C++, por exemplo, nasceu juntando duas coisas diferentes: a velocidade de C e as classes de SIMULA 67 — nenhuma das duas morreu por causa disso. Dois motivos para uma linguagem influenciar outra sem substituí-la: cada uma domina um nicho e tem muito código já escrito (ninguém joga fora décadas de Fortran e COBOL), e as boas ideias viajam sozinhas em artigos e livros, sem precisar que a linguagem faça sucesso no mercado.

3 — Os três resolviam o mesmo incômodo: escrever em código de máquina era horrível. Short Code e Speedcoding usavam um interpretador — liam o comando e executavam na hora, sem gerar programa traduzido. A série A-0 da Grace Hopper de fato traduzia, mas só colava sub-rotinas prontas de uma biblioteca, parecido com um linker. Chamar qualquer um deles de compilador moderno é errado porque falta tudo o que define um: análise da sintaxe, verificação de tipos e otimização. Nada disso existia ainda — a BNF, que permite descrever a sintaxe formalmente, só apareceu em 1959.

4 — Naquela época o computador custava muito mais caro que o programador. Então "gastar máquina para poupar tempo humano" era um péssimo negócio, e ninguém acreditava que um tradutor automático fizesse código tão bom quanto um humano. O IBM 704 ajudou, porque já tinha ponto flutuante em hardware e dispensava os interpretadores. O time do Fortran gastou cerca de 18 pessoas-ano quase só otimizando o código gerado, justamente para vencer essa desconfiança. Deu certo: em 1958 mais da metade do código do 704 já era Fortran. Anos depois a conta se inverteu — programador ficou caro, máquina ficou barata — e aí as linguagens puderam abrir mão de velocidade.

5 — Fortran é para números: arrays de tamanho fixo, memória reservada antes de rodar, laços e atribuições. É basicamente um espelho de como a máquina funciona. Lisp é para símbolos: só tem átomos e listas, cria memória conforme precisa, tem coleta de lixo e usa recursão no lugar de laços. E como o programa Lisp é escrito na mesma forma que ele manipula (uma lista), programa vira dado e dado vira programa. Muita coisa que hoje é normal — coleta de lixo, tipagem dinâmica, recursão — veio dali.

6 — Três heranças de ALGOL 60: a BNF (primeira forma de descrever a sintaxe de forma exata, base dos compiladores até hoje), a estrutura de blocos com variáveis locais (o { } que você usa todo dia) e o suporte a recursão. Ela não vingou comercialmente porque deixou a entrada e saída de fora da definição, o que estragou a portabilidade na prática, e porque a IBM já apostava no Fortran e não a apoiou. A lição é simples: fazer sucesso no mercado depende de fabricante, dinheiro e base instalada; influenciar depende só de ter ideias boas o bastante para serem copiadas.

11 — A linha imperativa: ALGOL 60 → ALGOL-W → Pascal (simples, para ensinar) e, por outro ramo, ALGOL 68 → BCPL/B → C (para escrever o Unix). Todas compartilham a mesma lógica: variável é uma caixa na memória, e você escreve passo a passo o que a máquina deve fazer. Prolog inverte isso. Você só declara os fatos e as regras que são verdadeiros; quem decide a ordem da busca e faz o vai-e-volta é o motor da linguagem. Você diz o que é verdade, não como calcular. O preço é perder o controle sobre o desempenho.

12 — Fatos: "João é pai de Maria" e "Maria é mãe de Pedro". Regra: "X é avô de Z se X é progenitor de Y e Y é progenitor de Z". Pergunta: "de quem João é avô?" → resposta: Pedro. Isso é programação lógica porque essa resposta não estava guardada em lugar nenhum — ela foi deduzida a partir da regra. Um banco de dados só devolve o que você salvou, e você mesmo precisa escrever o JOIN dizendo como cruzar as tabelas. Aqui a regra é o próprio programa, e a mesma regra responde de vários jeitos: quem são os netos, quem são os avôs, ou se um par específico é verdadeiro.

14 — Smalltalk é orientação a objetos pura: tudo é objeto, absolutamente tudo, e programar é trocar mensagens. C++ fez o oposto do purismo — manteve compatibilidade quase total com C para que todo programador de C pudesse migrar sem jogar código fora. Isso garantiu o sucesso, mas trouxe junto os perigos de C (ponteiros, memória manual) e deixou a linguagem gigante. Java pegou C++ e cortou o que dava mais dor de cabeça: herança múltipla, ponteiros, sobrecarga de operadores. Colocou coleta de lixo no lugar. E resolveu portabilidade compilando para bytecode, que roda em qualquer máquina que tenha a JVM — o mesmo arquivo compilado funciona em todo lugar. Foi isso que fez a Web impulsionar a linguagem.

16 — Perl nasceu para administrar Unix e mexer com texto. JavaScript nasceu para rodar dentro do navegador. PHP nasceu para rodar no servidor gerando HTML. Python nasceu focado em ser legível. Ruby é orientada a objetos pura. Lua nasceu para ser embutida dentro de outro programa (jogos, por exemplo) e por isso tem só uma estrutura de dados: a tabela. Chamar todas de "linguagem de script" só descreve como elas são executadas, não o que elas são. Elas guardam dados de formas diferentes, rodam em lugares diferentes e às vezes têm objetivos opostos — Perl busca ser compacta mesmo que fique ilegível, Python busca exatamente o contrário.

20 — Cálculo científico: Fortran ou C por baixo, Python por cima. Fortran nasceu para isso em 1957 e tem sessenta anos de bibliotecas numéricas confiáveis. Regras declarativas: Prolog ou um motor de regras — é o caso em que declarar o que vale é melhor do que programar a busca na mão. Web: JavaScript no navegador (não é escolha, é a única opção nativa) e Java, C# ou Python no servidor. Firmware: C, feita em 1972 justamente para sistemas, com acesso direto à memória e sem coleta de lixo; se o sistema for crítico, Ada ou Rust. Dois trade-offs: velocidade e controle contra segurança (C te dá controle total e a chance de errar feio; Ada e Rust protegem, mas são mais difíceis e têm menos gente no mercado) e usar poucas linguagens contra usar a ideal para cada parte (padronizar barateia contratação e manutenção; especializar encaixa melhor tecnicamente, mas multiplica o custo de integrar tudo).
